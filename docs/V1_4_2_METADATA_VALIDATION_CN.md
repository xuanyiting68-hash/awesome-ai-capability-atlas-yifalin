# V1.4.2 · Top 30 GitHub 元数据接入与验证记录

## 交付范围（2026-10-26）

- `top30.html`：从 `data/top30_evaluation.csv` 载入 30 个研究项目；额外从 `data/repo_metadata.json` 载入 Stars、Forks、GitHub SPDX 标识、最近 Push、归档状态。
- 新筛选：GitHub 已识别 SPDX / unknown；最近 90 天有 Push / 90 天未 Push 或数据缺失。
- 显示快照时间，避免将历史缓存冒充实时指标。
- GitHub API 提取的 SPDX 仅是许可证检测值，**不是针对商业使用、衍生作品、视频素材和依赖的授权审查**。
- 最近 Push 仅表明更新活动，**不等于有活跃维护者或安全响应**。
- 页面原有“未实测 / 许可待审 / 安全待审”保持不变；无元数据时只降级显示，不杜撰 Stars。

## 静态交叉核验

- Top 30 CSV 行数：30；元数据记录：133；30/30 仓库在该元数据快照中存在匹配键。
- 文件均已写入 GitHub 功能分支；未运行生产网站或真实浏览器 E2E，因此 UI 动作和发布后行为尚需验收。
- 数据时间戳应读取 `data/repo_metadata.json.generated_at_utc`，此记录不构成重新实时抓取的证据。

## 上线前验收

1. 在本地 HTTP 服务（非直接 `file://`）或 GitHub Pages 验证数据加载、移动布局、所有筛选组合和 CSV 导出。
2. 模拟元数据加载失败，页面应仍可用，并显示缺省数据而非虚构认证。
3. 模拟无 SPDX、归档和久未更新仓库，确认过滤结果和展示正确。
4. 确认外部 URL 不包含任意注入属性且保持 GitHub 原仓库跳转。
5. PR 合并后核对 Pages 是否部署，并检查静态 CSV 缓存刷新。
6. 对项目逐项阅读许可证原文、依赖许可和实际部署限制，才能改变 `not-reviewed` 状态。
