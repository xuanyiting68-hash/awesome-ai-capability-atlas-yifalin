V1.4.4 的目录同步成功，生成 `639b0d7`。随后串行队列中的元数据任务检出了触发时的旧提交，推送时被拒绝（`main -> main (fetch first)`）。失败任务没有覆盖远端数据，网站继续提供完整目录。

## 修复

- 两个自动写入任务保留同一串行队列，并在实际获得执行机会时显式检出最新 `main`，获取完整历史。
- 提交后先 rebase 最新 main，再推送；发生内容冲突则失败并保留远端，不强推。
- 将线上巡检改为可复用工作流，由 Pages 的 `verify-online` job 通过 `needs: deploy` 直接调用，并传入待验收 SHA。每日巡检和手动运行继续保留。
- 不再把另一个工作流的完成事件当作唯一发布验收触发器；Pages 整体结果包含实际线上巡检结果。

## 验证与边界

沿用 30 项 Python 测试、17 场景浏览器回归及发布产物冒烟检查。修复合并后必须再核对目录/元数据两条任务及 Pages 的 `verify-online / smoke` 实际结果。GitHub Actions 运行记录与 PR #5 说明保存最终状态。
